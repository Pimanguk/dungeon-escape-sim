# 시뮬레이터 사용법: 팀원 전략과 메타 직접 넣기

## 0. 시뮬레이터가 돌아가는 조건 (고정)

- 맵은 교수님 맵(`FinalExamGameCore\dungeonmap.dat`) 하나로 고정이에요.
- P0~P5 스폰 자리도 맵에 적힌 그대로 고정이에요. 판마다 바뀌는 건 "어느 플레이어가 어느 자리에 서는지"뿐이에요.
- H0(사람 플레이어)는 없어요. 6명만 경쟁해요.
- 우리 팀 `player0.c`는 항상 P0 역할이고, 상대 5명이 나머지 자리에 무작위로 섞여 서요.
- 예전의 랜덤 맵 옵션(`--gen`, `--map`)은 없앴어요. 쓰면 `bad arg`가 나와요.

## 1. 팀원 전략 넣기 (custom\team1.c ~ team5.c)

팀원 전략 칸이 5개 있어요. 처음에는 교수님 예제 AI를 부르는 임시 내용이 들어 있어요.

1. 팀원의 `playerN.c`를 열어서 `playerN_choose_command` 함수 전체를 복사해요. 위에 있는 `#define`이나 보조 함수도 같이 복사해요.
2. `StrategySim\custom\team1.c`를 열고 `strat_team1` 함수를 지운 뒤 복사한 내용을 붙여 넣어요.
3. 붙여 넣은 함수 이름을 `playerN_choose_command`에서 `strat_team1`로 바꿔요. 이름이 다르면 링크 에러가 나요.
4. 파일 맨 위의 `#include "../../FinalExamGameCore/player_api.h"` 줄은 그대로 둬요.
5. 보조 함수나 전역 변수가 있으면 앞에 `static`을 붙여요. 다른 파일과 이름이 겹치면 링크 에러(중복 정의)가 나요.
6. 메뉴에서 `b`(다시 빌드)를 눌러요. 명령어로는 `.\build.bat`이에요.
7. 같은 방법으로 team2~team5에 다른 팀원 전략을 넣어요. 5개가 다 안 차면 나머지는 임시 예제 AI로 남겨 둬요.

붙여 넣은 모습은 이래요.

```c
#include "../../FinalExamGameCore/player_api.h"

static int helper(int x) { return x + 1; }   /* 팀원의 보조 함수에는 static */

Command strat_team1(const char *state_path)   /* 이름만 strat_team1 로 */
{
    Snapshot s;
    FILE *file = fopen(state_path, "r");
    /* ... 팀원 코드 그대로 ... */
}
```

주의할 점이 두 가지 있어요.
- 시뮬레이터는 전략을 같은 프로그램 안에서 이어서 불러요. 그래서 `static`이나 전역 변수로 이전 턴 값을 기억하는 전략은 시뮬레이터에서만 기억이 남아요. 실제 게임은 매 턴 새 프로세스라서 기억이 사라져요. 팀원 전략이 이런 식이면 결과가 실제와 달라요.
- 상태 파일은 `fopen(state_path, "r")`과 `snapshot_read`로 읽어야 해요. 다른 방식으로 읽는 코드는 시뮬레이터에서 못 읽을 수 있어요.

## 2. 메타(상대 5명 구성) 만들기

메타는 `sim.c` 위쪽 `SCEN` 표의 한 줄이에요. 이미 두 줄이 들어 있어요.

```c
{"teams",   {"team1", "team2", "team3", "team4", "team5"}},     /* 팀원 전략 5개 */
{"my-meta", {"team1", "team2", "wounded", "gatehunter", "rusher"}}, /* 내가 짠 메타 */
```

- 앞의 문자열이 시나리오 이름이에요. 실행할 때 `--scenario 이름`으로 써요.
- 뒤의 `{ }` 안에는 상대 5명의 전략 이름을 정확히 5개 적어요. 우리(ours)는 자동으로 P0에 들어가요.
- 새 메타를 만들려면 한 줄을 복사해서 이름과 구성을 바꾸면 돼요. 예를 들면 이래요.

```c
{"wounded-heavy", {"wounded", "wounded", "wounded", "team1", "team2"}},
```

쓸 수 있는 전략 이름은 `sim.c`의 `STRATS` 표에 있는 것들이에요.

| 이름 | 내용 |
|---|---|
| `ours` | 우리 팀 `player0.c` (같은 전략 복제본을 상대로 쓰고 싶을 때) |
| `sample` | 교수님 예제 AI (player1) |
| `rusher` | 열쇠로 직진, 들었으면 출구로, 남이 들었으면 쫓아가 공격 |
| `wounded` | HP가 가장 낮은 살아 있는 적(HP 1 우선)을 찾아가 공격. 제자리 대기 없음. 다친 적이 없으면 돌진 |
| `gatehunter` | 통로에서 기다리는 적을 찾아가 공격 |
| `hunter` | 열쇠 소유자만 쫓아다님 |
| `team1`~`team5` | 팀원 전략 칸 (1번에서 넣은 것) |

`team6` 이상이 필요하면 세 군데를 고쳐요.
1. `custom\team6.c`를 `team5.c`를 복사해서 만들고 함수 이름을 `strat_team6`으로 바꿔요.
2. `sim.c` 위쪽의 `extern`(함수 선언) 줄에 `Command strat_team6(const char *);`를 추가해요.
3. `STRATS` 표에 `{"team6", strat_team6},`를 추가해요.

다 고치고 나면 `sim.c`를 고쳤으니 `b`(다시 빌드)를 눌러요.

## 3. 돌리기

가장 쉬운 방법은 `시뮬레이션실행.bat`을 더블클릭하는 거예요. 메뉴는 이래요.
- 1~9: 시나리오 한 판을 보기. 화면으로 턴마다 재생하거나 텍스트 파일로 저장할 수 있어요.
- `a`: 전체 기록표를 만들어서 `results.md`에 추가해요(시나리오마다 300판).
- `b`: 코드를 고친 뒤 다시 빌드해요.

명령어로 돌리려면 `StrategySim` 폴더에서 이렇게 써요.

```powershell
.\sim.exe --games 300 --seed 7 --scenario my-meta      # 내 메타 300판
.\sim.exe --games 300 --seed 7 --scenario teams        # 팀원 5명끼리 (우리 포함 6명)
.\sim.exe --games 1 --seed 42 --scenario my-meta --watch 1000   # 한 판을 화면으로 보기 (턴 간격 1초)
.\sim.exe --games 300 --seed 7                         # 모든 시나리오
```

같은 `--seed`를 쓰면 같은 판들로 비교해서 공정해요. 전략을 고친 뒤에는 seed를 그대로 두고 다시 돌려서 승률이 오르는지 봐요.

## 4. 결과 읽는 법

```
scenario     win%   draw%  avgT  deaths cancel max_ms  winners
my-meta      84.0%  1.0%   28.9  0.41   0.70   0.26    ours:84 rusher:13 wounded:2
```

- `win%`: 우리 승률이에요. 6명 경쟁이라 운으로만 이기면 약 16.7%예요.
- `draw%`: 200턴 안에 아무도 못 나가서 무승부인 비율이에요.
- `avgT`: 이길 때 평균 몇 턴 걸렸는지예요.
- `deaths`, `cancel`: 판당 우리 사망 수와 우리 명령이 취소된 횟수예요(취소되면 피해 1).
- `max_ms`: 우리 함수가 한 번 부를 때 걸린 최대 시간이에요. 실제 제한은 1500ms예요.
- `winners`: 누가 몇 판 이겼는지예요.

## 5. 메모리 누수와 파일 닫기 (교수님 감점 항목)

- 시뮬레이터는 모든 전략(팀원 전략 포함)의 `fopen`/`fclose` 짝을 검사해요. `fclose`를 빼먹으면 `P1(team1) FILE LEAK turn=...`이 화면에 나와요.
- `malloc` 누수는 시뮬레이터에서 못 잡아요(Release로 빌드해서 그래요). 팀원 코드에 `malloc`이 있으면 교수님 코어(Debug)로 확인해요.
- 교수님 코어 확인 방법은 이래요. Visual Studio에서 `FinalExamGameCore`를 Debug로 빌드하고 `FinalExamGameCore.exe --auto --fast --plain`을 한 번 돌려요. 그다음 `bin\x64\Debug\run-숫자\playerN_diagnostics.log`를 열어요. 파일이 비어 있으면 누수가 없다는 뜻이고, 내용이 있으면 소스 파일명과 줄 번호가 적혀 있어요.
- 우리 팀 `player0.c`는 `malloc`을 쓰지 않아요. `fopen`은 한 번이고 곧바로 `fclose`해요. 지난 실행 진단 로그 114개가 모두 비어 있었어요.

## 6. 6팀을 내 마음대로 정해서 돌리기 (`--teams`)

```powershell
.\sim.exe --games 500 --seed 7 --teams ours,safe,vulture,exitguard,brawler,team1
```

- 이름 6개를 쉼표로 적어요(공백 없이). **첫 번째가 기준 팀**이라 `win%`는 첫 번째 팀의 승률이에요.
- 6개 자리는 판마다 무작위로 섞여요. 같은 이름을 여러 번 써도 돼요(`ours,ours,wounded,...`).
- 우리를 빼고 싶으면 첫 번째를 다른 팀으로 쓰면 돼요(`team1,team2,team3,team4,team5,ours`).
- 메뉴(`시뮬레이션실행.bat`)에서는 `c`를 누르면 같은 걸 물어봐요.

## 7. 쓸 수 있는 전략 (새로 추가한 것)

| 이름 | 하는 일 | 겨냥하는 약점 |
|---|---|---|
| `safe` | 조심스러운 주자. 적이 붙은 칸을 피해 열쇠/출구로 감 | 서로 피하다 무승부 만들기 |
| `vulture` | 열쇠에서 2칸 떨어져 기다리다 누가 줍으면 쫓아가 공격 | 줍는 순간 노출 |
| `exitguard` | 남이 열쇠를 들면 출구 바로 옆 칸을 차지해 길을 막음 | 출구 진입 방해 |
| `brawler` | 열쇠 무시, 가장 가까운 적에게 붙어서 계속 공격 | 이동 중 피해 |
| `chaos` | 무작위 이동. 규칙 충돌을 많이 만듦 | 버그/예외 상황 탐지 |

예: `--teams ours,exitguard,exitguard,vulture,vulture,brawler`는 우리를 막는 메타예요.
시나리오 표에도 `counter`, `counter-gate`, `safe-mix`, `chaos`가 들어 있어요.

## 8. 코어 버그 탐침 (`probe.exe`)

```powershell
.\build_probe.bat        # 한 번만
.\probe.exe --games 2000 --seed 5
```

교수님 `game.c`/`snapshot.c`를 그대로 링크해서 아래를 확인해요. `FAIL`이 0이면 통과, `NOTE`는 알아둘 점이에요.
- A: 규칙 경계 상황 30여 개(순환 이동, 연쇄 취소, 시체 칸 이동, 대각선 모서리 공격, 잘못된 enum, 휴식 턴 포화 등)
- B: 7명이 무작위·잘못된 명령을 내는 판을 수천 판 돌리며 매 턴 불변식 검사(같은 칸 중복, 벽 안, 죽은 열쇠 소유자, 잘못된 승자 등)
- C: 맵 로더에 이상한 파일을 넣어 판정(BOM, 탭, 중복, 비정방형, 빈 줄 등)
- D: 상태 파일을 변조해 `snapshot_read`와 우리 팀 `player0.c`가 죽지 않고 FILE도 새지 않는지
- E: 무작위 상태에서 우리 명령이 규칙상 취소(자해 피해)되지 않는지
