# 교수님 코어 버그 검토 결과 (가산점용)

검토 대상: `FinalExamGameCore`의 `game.c`, `snapshot.c`, `runner.c`, `main.c`, `input.c`, `display.c`, `diagnostics.c`, `tests.c`를 `Rule.txt`와 줄 단위로 대조.
확인 방법: `StrategySim\probe.exe`(소스 `bugprobe.c`)로 교수님 `game.c`/`snapshot.c`를 그대로 링크해 실행.

## 결론
- **규칙을 어기는 버그는 찾지 못했어요.** 규칙 경계 상황 30여 개와 무작위 판 약 60만 턴에서 불변식 위반이 0건이에요.
- 아래는 버그라고 단정하기는 어렵지만 교수님께 말씀드릴 만한 **관찰 사항**이에요. 해석은 교수님 판단이에요.

## 관찰 사항

| # | 위치 | 내용 | 영향 |
|---|---|---|---|
| 1 | `runner.c:15-18` | `--auto`에서 H0(ID 6)는 `player0_choose_command`를 불러요. `Rule.txt` 9절은 "7명 모두 예제 AI"라고 써 있어요. 그래서 `--auto`에서는 P0와 H0가 같은 코드(우리 코드)라서 서로 열쇠를 다퉈요 | 자동 실행 결과를 해석할 때 주의. 시뮬레이터는 H0를 뺀 6명 기준 |
| 2 | `snapshot.c:41-49` | `snapshot_read`는 `size`, `self`, `key_owner`, 플레이어 `pos`, `hp`만 범위 검사해요. `key`, `key_start`, `exit`, `spawn` 좌표는 검사하지 않아요 | 정상 코어가 쓴 파일에서는 문제 없어요. 변조된 파일이면 학생 코드가 배열 밖을 읽을 수 있어요(우리 `player0.c`는 변조 파일 3000건에서 안전) |
| 3 | `game.c:164`, `snapshot.c:11` | 열쇠를 집어도 `g->key`는 집은 자리 좌표로 남아요. 상태 파일 머리 줄의 `key.x key.y`가 "소유자가 있는 동안은 옛 좌표"예요 | `Rule.txt`에 설명이 없어요. 학생은 `key_owner`가 -1일 때만 `key`를 믿어야 해요 |
| 4 | `game.c:33` | 맵 파일 끝에 **빈 줄이 하나 더** 있으면 "Map requires two ASCII characters per cell"로 로딩 실패해요 | `Rule.txt`는 "마지막 줄 개행 생략"만 말해요. 맵 파일을 편집기에서 저장할 때 조심 |
| 5 | `main.c:70`, `game.c:97` | 턴 시작 화면의 "명령:" 값은 `begin_turn`에서 -1로 지워진 뒤라 항상 -1로 보여요(결과 화면에서만 실제 값) | 표시만의 문제 |

## 확인한 규칙 (모두 Rule.txt대로 동작)
순환 이동·자리 교환 허용 / 앞선 이동 취소 시 연쇄 취소 / 시체 칸으로 이동 가능 / 상대가 비우는 칸에 열쇠 버리기 가능 / 줍기와 같은 칸 진입 동시 성공 / 여러 명 공격이 겹쳐도 HP -1 / 벽 모서리 너머 대각선 공격 가능 / 필드 밖 공격은 무해 / 잘못된 enum 7종 취소+피해 / 휴식 턴 포화(64회 2^63, 65회 UINT64_MAX) / 승리 후 `game_resolve` 무시 / 출구에 열쇠 버리기 취소 / 같은 턴 떨어지는 열쇠 못 줍기 / 열쇠 소유자 자기 취소로 사망 시 그 자리에 드롭.

## 우리 코드 쪽 확인
- 변조 상태 파일 3000건: 합법 enum 반환, FILE 누수 0.
- 무작위 상태 20000건: 규칙상 취소되는 명령 0건.
- `/W4` 경고 없음, malloc 없음.
